# my-andrej-karpathy-skills

**Claude Code와 OpenAI Codex에서 사용하는 개인용 AI 코딩 지침 모음입니다.**

AI가 요구사항을 확인하고, 필요한 범위만 수정하며, 결과를 검증하도록 돕습니다. 도구별 마크다운 지침 파일을 전역 또는 프로젝트 단위로 적용할 수 있습니다.

## 제공 파일

| 파일 | 대상 도구 | 기본 전역 적용 경로 | 프로젝트 적용 경로 |
| --- | --- | --- | --- |
| [CLAUDE.md](./CLAUDE.md) | Claude Code | `~/.claude/CLAUDE.md` | 프로젝트 루트의 `CLAUDE.md` |
| [AGENTS.md](./AGENTS.md) | OpenAI Codex | `~/.codex/AGENTS.md` | 프로젝트 루트의 `AGENTS.md` |

전역 파일은 같은 사용자 환경의 여러 프로젝트에 공통 지침을 제공합니다. 프로젝트 파일에는 해당 프로젝트의 구조, 실행 명령, 테스트 방법 등 구체적인 규칙을 추가합니다.

> Codex 파일명은 대문자 복수형인 **`AGENTS.md`**입니다.

## 핵심 원칙

두 파일은 다음 10가지 원칙을 공유합니다.

| 번호 | 원칙 | 적용 내용 |
| --- | --- | --- |
| 1 | 구현 전에 생각하기 | 가정과 불확실성을 드러내고, 결과에 영향을 주는 모호함을 확인합니다. |
| 2 | 단순함 우선 | 요청한 문제를 해결하는 최소한의 코드만 작성합니다. |
| 3 | 필요한 부분만 수정 | 기존 스타일을 따르고, 요청과 무관한 리팩터링을 피합니다. |
| 4 | 검증 가능한 목표 | 성공 기준과 단계별 확인 방법을 정합니다. |
| 5 | 자연스러운 한국어 출력 | 한국어 문장을 콜론으로 끝내지 않습니다. 코드와 키·값 표기는 예외입니다. |
| 6 | 한국어 파일 설명 | 새 소스 파일 상단에 역할을 설명하는 한국어 주석을 작성합니다. |
| 7 | 계획·체크리스트·맥락 기록 | 단순하지 않은 작업은 계획, 진행 상황, 결정 이유를 문서로 남깁니다. |
| 8 | 완료 전에 검증 | 코드를 수정했다면 테스트를 실행하고, 테스트가 없으면 적용 가능한 빌드·컴파일을 확인합니다. |
| 9 | 의미 단위 커밋 | 하나의 논리적 변경이 완성되면 커밋합니다. |
| 10 | 실제 오류 확인 | 오류 메시지와 로그를 읽고 원인을 확인한 뒤 수정합니다. |

## 두 파일의 차이

`AGENTS.md`는 `CLAUDE.md`의 원칙을 바탕으로 Codex의 작업 방식에 맞게 보완한 버전입니다.

| 항목 | CLAUDE.md | AGENTS.md |
| --- | --- | --- |
| 모호한 요구사항 | 가정과 불확실성을 확인하고 질문합니다. | 결과에 영향을 주는 모호함은 질문하되, 사소하고 되돌릴 수 있는 선택은 가정을 밝히고 진행합니다. |
| 작업 문서 | 계획만 주어진 경우 체크리스트·맥락 노트 작성 여부를 먼저 묻습니다. | 계획만 주어져도 누락된 문서를 자동으로 만들고 진행합니다. |
| 문서 관리 | 계획, 체크리스트, 맥락 노트를 요구합니다. | 기존 문서와 위치를 재사용하고, 간단한 질문이나 사소한 수정은 3종 문서 생성에서 제외합니다. |
| 검증 결과 | 테스트 또는 빌드 결과를 확인합니다. | 검증이 막힌 이유와 미검증 범위를 보고하고, 기존 실패와 변경으로 인한 실패를 구분합니다. |
| 커밋 범위 | 의미 있는 변경 단위로 커밋합니다. | 기존 사용자 변경을 보호하고, 해당 작업의 변경만 선별해 커밋합니다. |
| 적용 범위 | 프로젝트별 지침과 함께 사용합니다. | 전역·프로젝트·하위 디렉터리 지침과 전역 override의 우선순위를 명시합니다. |

## 설치 방법

### 1. 저장소 내려받기

```bash
git clone https://github.com/jong-bae/my-andrej-karpathy-skills.git
cd my-andrej-karpathy-skills
```

아래 명령은 내려받은 저장소 폴더에서 실행합니다. 이미 사용 중인 지침 파일이 있다면 기존 내용을 백업하고 필요한 규칙을 병합하세요.

### 2. 전역 적용

사용하는 도구에 해당하는 파일을 설치합니다.

**macOS / Linux / WSL / Git Bash**

Claude Code용입니다. `-i` 옵션은 기존 파일이 있을 때 덮어쓰기 전에 확인합니다.

```bash
mkdir -p ~/.claude
cp -i ./CLAUDE.md ~/.claude/CLAUDE.md
```

Codex용입니다.

```bash
mkdir -p ~/.codex
cp -i ./AGENTS.md ~/.codex/AGENTS.md
```

**Windows PowerShell**

사용자 홈 폴더 아래에 해당 디렉터리를 만든 뒤 파일을 복사합니다. 대상 파일이 이미 있으면 기존 내용을 확인하고 병합하세요.

```powershell
New-Item -ItemType Directory -Force -Path "$HOME\.claude", "$HOME\.codex" | Out-Null

if (-not (Test-Path "$HOME\.claude\CLAUDE.md")) {
    Copy-Item .\CLAUDE.md "$HOME\.claude\CLAUDE.md"
}

if (-not (Test-Path "$HOME\.codex\AGENTS.md")) {
    Copy-Item .\AGENTS.md "$HOME\.codex\AGENTS.md"
}
```

| 도구 | Windows 기본 전역 경로 |
| --- | --- |
| Claude Code | `%USERPROFILE%\.claude\CLAUDE.md` |
| Codex | `%USERPROFILE%\.codex\AGENTS.md` |

설치하거나 내용을 수정한 뒤에는 새 세션을 시작합니다.

### 3. 특정 프로젝트에만 적용

전역 대신 특정 프로젝트에 적용하려면 해당 프로젝트 루트에 파일을 복사합니다.

```bash
cp -i ./CLAUDE.md /path/to/your-project/CLAUDE.md
cp -i ./AGENTS.md /path/to/your-project/AGENTS.md
```

사용하는 도구에 해당하는 명령만 실행하면 됩니다. `/path/to/your-project`는 실제 프로젝트 경로로 바꾸세요. 프로젝트에 기존 파일이 있다면 내용을 병합합니다.

## Codex 적용 시 확인할 사항

- `CODEX_HOME`을 별도로 설정했다면 `~/.codex` 대신 해당 폴더의 `AGENTS.md`에 설치합니다.
- 전역 폴더에 비어 있지 않은 `AGENTS.override.md`가 있으면 전역 `AGENTS.md`보다 우선해 선택됩니다.
- 프로젝트와 하위 디렉터리의 지침은 전역 기본 지침을 구체화하며, 충돌하는 내용은 작업 위치에 더 가까운 지침이 우선합니다.
- Codex용 파일은 `AGENTS.md`로 설치합니다. `CLAUDE.md`의 자동 로딩을 전제로 하지 않습니다.

새 Codex 세션에서 다음과 같이 요청해 적용 내용을 확인할 수 있습니다.

```text
현재 적용된 전역 지침과 프로젝트 지침을 요약해줘.
```

## 작업 문서 활용

단순하지 않은 개발 작업에서는 다음 문서를 활용합니다. Codex용 지침은 기존에 같은 역할을 하는 문서가 있으면 재사용합니다.

| 문서 | 역할 |
| --- | --- |
| 계획 문서 | 무엇을 왜 만드는지, 작업 범위와 검증 방법을 기록합니다. Codex용 기본 파일명은 `plan.md`입니다. |
| `checklist.md` | 구체적인 작업을 체크박스로 나누고 진행 상태를 갱신합니다. |
| `context-notes.md` | 주요 결정과 이유, 검증 결과, 장애물, 다음 작업을 기록합니다. |

예를 들어 다음처럼 요청할 수 있습니다.

```text
사용자 로그인 기능을 구현해줘.

먼저 기존 구조와 프로젝트 지침을 확인하고,
계획·체크리스트·맥락 노트를 작성하거나 갱신해줘.
필요한 범위만 수정한 뒤 관련 테스트를 실행하고 결과를 알려줘.
```

## 나에게 맞게 수정하기

- 프로젝트의 언어와 도구에 맞는 테스트·빌드 명령을 추가합니다.
- 문서 저장 위치와 파일명은 기존 프로젝트 규칙에 맞춥니다.
- 두 파일에는 의미 단위 자동 커밋 지침이 들어 있습니다. 커밋을 직접 관리하려면 해당 규칙을 수정합니다.
- Codex용 지침에서 로컬 커밋은 원격 push나 배포의 승인으로 간주하지 않습니다.
- 설치는 파일 복사 방식입니다. 저장소를 업데이트해도 전역 파일은 자동 갱신되지 않으므로 변경 내용을 확인한 뒤 다시 병합합니다.
